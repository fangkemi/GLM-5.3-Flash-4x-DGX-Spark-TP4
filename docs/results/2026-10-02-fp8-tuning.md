# FP8 switchless single-request tuning, 2026-10-02

Four DGX Spark nodes, physical/TP order spark1 → spark2 → spark4 → sparkX.
Target: dealignai/GLM-5.3-Flash-UNCENSORED-FP8. Drafter: original BF16
incoai/GLM-5.3-Flash-DFlash2. Image: glm53-roce:v11-b58f34ea, vLLM
487ecf187. This is the FP8 switchless configuration, separate from the
NVFP4/Marlin switched release in `profiles/current.env`.

## Selected recipe

The updated [example](../../.env.fp8.dflash.switchless.example) uses:

```sh
BATCHED_TOKENS=8192
MAX_SEQS=3
K_HI=3
K_LO=3
SPEC_TABLE='[[1,3,3]]'
EXTRA_ENV="GLM_MAMBA_ALIGN_FIX=1 GLM_DRAFT_CONV_FUSED=1 GLM_DRAFT_CONV_FUSED_QUAL=1 GLM_ROUTER_DEDUP=1"
```

Keep `GLM5NEXT_PATCH=0`, `KV_DTYPE=auto`, `SCHEDULER_CLS=none` and Triton
MoE/linear backends for this target. The deployed fusion qualifier used its
on-by-default value; the example sets it explicitly. MAX_SEQS=4 was not
screened because the requested workload is single-request low latency.

Final boot: 17 GiB KV allocation per rank, 1,469,300 shared KV tokens,
maximum model context 1,048,576. Four ranks running, no OOM or restart,
health 200 and model identity verified. After measurement, host MemAvailable
was 6.28 / 8.63 / 8.03 / 8.53 GiB. This is an observed sample, not a peak-memory
or full-context stress test. The shared pool cannot fit three simultaneous
1M-token sequences.

## Fixed draft length comparison

Temperature zero, thinking off, min/max output 256 tokens. Three synthetic
prompt types; full-length warmup for every type excluded, then three rounds
with alternating prompt order. Request-success counters exclude other traffic.
All measured requests produced 256 tokens; no contaminated rows.

| K | Prose tok/s | Code tok/s | JSON tok/s | Equal-weight geometric speed vs K=3 |
|---|---:|---:|---:|---:|
| 2 | 31.97 | 43.76 | 39.40 | −8.45% |
| 3 | 33.87 | 50.05 | 42.38 | reference |
| 4 | 31.34 | 51.20 | 39.99 | −3.70% |

Cells are median decode rates. K=4 slightly improved code but regressed prose
and JSON; retain K=3. These are sequential boots and short synthetic samples,
not proof that K=3 wins for every prompt or concurrency level.

## Qualified convolution and router dedup

Five variants in one boot: two identical controls, convolution only, router
only, both. Separate target and drafter graph sets, complete warmup of all
variants, four rounds with reversed order on alternate rounds; drop the first
round for statistics, leaving nine samples per variant. All four ranks agreed
on switching and replayed only the block's target graph set. No foreign rows.

| Variant | Median step ms | Prose tok/s | Code tok/s | JSON tok/s |
|---|---:|---:|---:|---:|
| Control A | 67.691 | 32.86 | 51.17 | 41.86 |
| Identical control A/A | 67.644 | 34.59 | 50.56 | 45.38 |
| Fused convolution | 67.499 | 34.34 | 50.70 | 42.80 |
| Router dedup | 67.359 | 35.64 | 51.16 | 45.07 |
| Both | 66.777 | 32.80 | 51.49 | 45.60 |

Both reduced paired step time by 1.09% vs A and 1.27% vs A/A, with a reduction
in all three retained rounds against either control. The exploratory bootstrap
intervals over those three rounds were −2.02% to −0.40% and −1.91% to −0.82%.
Individual switches did not establish the same clear reduction.

Token/s vs A increased 3.82%, but the identical control itself increased 4.35%.
Against A/A, the combined token/s change was −0.41% with an interval crossing
zero. Therefore **overall throughput improvement was not established**. Retain
both for their small, consistent step-time reduction and successful checks.

## Validation and final repeat

Each configuration and the final deployment passed 11/11 semantic checks,
including 13,170-token record retrieval across the prefill budget. Strict JSON
format compliance was 9/11 throughout: two responses included explanatory text
around correctly valued JSON. The unchanged baseline had the same failures.
This is a bounded synthetic panel, not a general capability evaluation.

On every rank, three convolution shape/layout keys passed the default
synthetic BF16 bitwise comparison with the original implementation; zero bad
keys. Router diagnostics checked 2,436 eager MoE calls with zero placeholder
violations, skipped 2,688 duplicate calls and retained zero old-path calls.
Diagnostics are removed from the final production environment. The test-only
AB/dev-mode flags were removed; `/collective_rpc` returned 404 after redeploy.

Free-form greedy outputs were not reproducible even between identical controls
(0/9 identical text pairs). Neither identical text nor universal quality
preservation is claimed.

| Final production repeat | Median decode tok/s | Median TTFT ms, 256-token output | TTFT recheck ms, six 16-token outputs |
|---|---:|---:|---:|
| Prose | 35.88 | 329 | 347 |
| Code | 51.71 | 384 | 351 |
| JSON | 45.76 | 265 | 303 |

The short-output recheck investigated the higher initial code TTFT. Output
budgets differ, so it does not replace the original comparison. TTFT varied;
**first-token improvement was not established**. The final higher decode rates
are observed samples and cannot all be attributed to the kernel changes.

## Reproduce

Use the [FP8 deployment guide](../fp8-deployment.md) to prepare images, weights
and switchless NCCL. Adjust the example's addresses and paths. Stop using the
old profile, then use fresh container names and overlay directories for each
candidate; preserve the stopped runtime. Start/restart through a named tmux
session. Keep passwords and authentication prompts in an interactive tmux pane.

The benchmark is stdlib-only and sends bounded synthetic requests:

```sh
python3 bench/fp8_tune.py k3 --base http://HEAD:8888 --out logs/fp8-tune
```

For K=2/4, change both K_HI and K_LO and the third SPEC_TABLE value, then restart
with fresh runtime names. Capture sizes must include n*(K+1) for n=1..MAX_SEQS.
Keep prefill, model, precision, KV allocation and backends fixed. Run the same
benchmark under labels k2/k4. Warmups and foreign-traffic detection are built in.
The script does not restart services.

For in-boot kernel comparisons use `scripts/ab_inboot_glm.py` and the test-only
`overlay/glm_ab.py`. Bind the test service to loopback and use a local SSH tunnel.
Temporary EXTRA_ENV additions:

```sh
VLLM_SERVER_DEV_MODE=1 GLM_AB_VARIANTS=5 GLM_AB_ALLOW_AA=1 GLM_AB_DRAFT_SETS=1
GLM_AB_V0=GLM_DRAFT_CONV_FUSED=0+GLM_ROUTER_DEDUP=0
GLM_AB_V1=GLM_DRAFT_CONV_FUSED=0+GLM_ROUTER_DEDUP=0
GLM_AB_V2=GLM_DRAFT_CONV_FUSED=1+GLM_ROUTER_DEDUP=0
GLM_AB_V3=GLM_DRAFT_CONV_FUSED=0+GLM_ROUTER_DEDUP=1
GLM_AB_V4=GLM_DRAFT_CONV_FUSED=1+GLM_ROUTER_DEDUP=1
GLM_ROUTER_DEDUP_CHECK=1
```

To match this experiment's fixed lengths and thinking-off template, replace the
driver's chat method with the benchmark method before invoking `main()`:

```python
# Run from repository root; append driver arguments to this invocation.
import sys
from pathlib import Path
sys.path[:0] = [str(Path('bench').resolve()), str(Path('scripts').resolve())]
import fp8_tune as b
import ab_inboot_glm as d

def chat(self, prompt, max_tokens):
    r = b.chat(self.base, prompt, tokens=max_tokens, fixed=True)
    return dict(ttft=r['ttft_s'], tokens=r['tokens'], text=r['text'],
                total=r['ttft_s'] + (r['tokens'] - 1) / r['decode_tps'])

d.Engine.chat = chat
# Write b.PROMPTS as JSONL records {kind, prompt}; pass --prompts FILE.
# Arguments: LABEL --base http://127.0.0.1:18888 --model glm-5.3-flash
# --rounds 4 --drop-rounds 1 --max-tokens 256 --prompts FILE
# Run b.run_quality for each switched variant and inspect eng.status()
# kernel_checks on all ranks as well as the driver's replay checks.
d.main()
```

Remove AB/dev-mode/check flags and restore normal binding with fresh runtime
names after comparison. Then rerun quality/performance and verify all four
ranks, health, model identity and actual KV capacity.
